# Broad UI anti-slop audit 011

**Date:** 2026-10-03  
**Mode:** AFTER, session override  
**Scope:** Home, Dashboard, Admin Hub and Admin Hub pages, all requested medical surfaces, KF, Archive, Reports, and Records.  
**Method:** Read-only source audit with 13 independent surface reviews and one deduplication pass.  
**Source changes:** None.

## Executive summary

The audit found **73 concrete findings** across the requested surfaces:

- **26 HIGH** findings, mainly around failed queries presenting as empty/zero data, missing persistence, incomplete medical save state, and inaccessible clinical inputs.
- **37 MEDIUM** findings, mainly around responsive reflow, tab/disclosure semantics, labeling, retry affordances, and export truthfulness.
- **10 LOW** findings, mainly around decorative comments, mixed-language copy, and generic visual decoration.

The most important shared pattern is **truthful state handling**: several pages distinguish loading from success, but do not distinguish failed requests from successful empty data. In clinical and accounting contexts, that can make incomplete or unavailable data look valid.

## Findings

### Home and landing surfaces

#### F-001. Main home can render as a blank landing page during permission loading or failure

- **Priority:** HIGH
- **Rule:** R-31
- **Evidence:** `client/src/pages/MainHome.tsx:339-347,368-385,565-590`; `client/src/hooks/usePermissions.ts:34-35`. `visibleHomeCards` requires `permissionsResolved`, but the grid has no loading, error, or no-access branch.
- **Why:** Users receive no feedback, and a permission/API failure is indistinguishable from an empty menu.
- **Fix:** Render explicit loading, retryable permission-error, and deliberate no-access states around the grid.

#### F-002. Patient search errors appear as false no-results

- **Priority:** HIGH
- **Rule:** R-31/R-32
- **Evidence:** `client/src/pages/PatientHubHome.tsx:84-89,132-143` branches on `isFetching` and `results.length`; `searchQuery.isError` is not checked.
- **Why:** A failed request can tell staff that no patient exists, which is unsafe in a clinical workflow.
- **Fix:** Add an error branch with retry; reserve no-results copy for successful empty responses.

#### F-003. Clinics landing silently collapses when permissions are unresolved

- **Priority:** MEDIUM
- **Rule:** R-31
- **Evidence:** `client/src/pages/ClinicsHubShell.tsx:109-110,154-165`; `client/src/hooks/usePermissions.ts:30-37`. The filtered module grid is rendered without permission loading/error state.
- **Why:** Permission loading, permission failure, and zero accessible modules all look like a broken or empty landing page.
- **Fix:** Consume permission query state and show loading, retryable error, or explicit no-access messaging.

#### F-004. Main landing keeps a cramped three-column mobile grid

- **Priority:** MEDIUM
- **Rule:** R-27
- **Evidence:** `client/src/pages/MainHome.tsx:395-396,411-414,583-585` uses `grid-cols-3`, `min-h-[116px]`, `p-2.5`, `text-[11px]`, and `text-[9px]` below `sm`.
- **Why:** Arabic labels and helpers are likely cramped on phones and long labels are forced into narrow cards.
- **Fix:** Use one or two columns at narrow widths or increase card width/type before moving to denser columns at larger breakpoints.

#### F-005. Main landing hierarchy mixes Arabic with implementation-style English copy

- **Priority:** LOW
- **Rule:** R-03/R-32
- **Evidence:** `client/src/pages/MainHome.tsx:59-63,186-189,571-579` includes `MAIN MENU`, `Workflow`, `AutoRef`, `Refractions`, `Pentacam`, and `Medical Reports` alongside Arabic labels.
- **Why:** The primary navigation feels unfinished for an Arabic RTL audience and scanability is weaker.
- **Fix:** Localize the eyebrow, helpers, and module labels consistently, or define an intentional bilingual treatment.

#### F-006. Patient hub contains decorative narration comments

- **Priority:** LOW
- **Rule:** R-35
- **Evidence:** `client/src/pages/PatientHubHome.tsx:111,131,184` comments merely state that input, results, and recent sections are visible or inline.
- **Why:** They add maintenance noise without explaining a constraint.
- **Fix:** Remove them or replace them only with a short rationale tied to a real product or technical constraint.

### Dashboard and clinical portal

#### F-007. Dashboard data failures appear as valid zero or empty data

- **Priority:** HIGH
- **Rule:** R-27

#### F-008. Clinical decision controls can overflow on narrow screens

- **Priority:** HIGH
- **Rule:** R-03/R-35
- **Evidence:** `client/src/features/clinical-suite/ClinicalDecisionSupport.tsx:151-152,184,215` uses `flex-nowrap` and fixed widths `w-64`, `w-44`, and `w-40`.

#### F-009. Secondary dashboard tabs lack complete tab semantics

- **Rule:** R-32

- **Why:** Assistive technology cannot identify the tab set, selected tab, or associated panel.

#### F-010. Clinical decision support has no load/error state for an existing plan

- **Rule:** R-27

- **Why:** A slow or failed fetch looks like a new blank plan, and a save can replace existing data without explaining the retrieval failure.
- **Fix:** Show loading and retryable error states; disable save until retrieval succeeds or the user explicitly chooses trial mode.

#### F-011. Diagnostic image failures appear as an empty gallery

- **Priority:** MEDIUM
- **Rule:** R-27

#### F-012. Dashboard contains decorative separator and narration comments
