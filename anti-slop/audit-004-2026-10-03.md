Scope: `client/src/features/attendance/**` and `client/src/features/salary/*`, plus the shared pieces they rely on (`index.css`, `styles/design-system.css`, `components/ui/button.tsx`, `date-input.tsx`).

## HIGH

1. **Focus ring is too faint** (R-32, R-34). The global base style is `outline-ring/50` (`index.css:348`, `styles/mobile.css:162`, `styles/web.css:739`). Measured in the browser: `outline: solid 2px` at 50% alpha. The ring `#003d82` at 50% over white is `#809ec0`, which is 2.77:1 against the white card and 2.74:1 against the page background. Below the 3:1 bar for non-text indicators. Dark theme passes narrowly (3.11:1). Fix: use the full `--ring` colour.
2. **The shift drawers do not trap focus** (R-32, R-26). Opened `ShiftManagement`'s drawer, pressed Tab 40 times: focus left the dialog and landed on "إيقاف" in the page behind it, while the dialog stayed open. Same structure in `salary/SalaryBasics.tsx` (drawer at `role="dialog"`). Escape works (fixed earlier), but Tab and screen-reader virtual cursor reach the covered page. Fix: use the shared `Dialog`/`Sheet` (Radix traps focus and restores it), or add a focus trap plus `inert` on the page behind.
3. **Form-field borders fail non-text contrast** (non-text contrast). About 218 raw `<input>`/`<select>`/`<textarea>` use `border-border` (`#ced4db` on white = 1.49:1; dark `#515b68` on the card = 2.29:1). The shared `Input` uses `border-input` (3.28:1 light, 5.10:1 dark) and passes. Worst files: `salary/CommissionPools.tsx` (36), `attendance/ShiftAssignments.tsx` (26), `salary/ShiftSchedule.tsx` (22), `attendance/EmployeesList.tsx` (15), `ScheduleSwap.tsx` (12). `Button variant="outline"` also uses the default border colour (`button.tsx:15`), so every outline button's edge is 1.49:1. Fix: `border-input` on raw controls and on the outline variant.
4. **Roster day cells show the shift type by dot colour only** (colour-only feedback, C-4). `salary/ShiftSchedule.tsx:996-1018`: morning, evening and holiday are 6px dots (orange, blue, yellow) with no text; the cell's `aria-label` ("عرض ورديات يوم …") does not say which shifts exist; when a day is selected all three dots turn the same `primary-foreground`, so they cannot be told apart at all. The legend below names the colours, which helps sighted users only. Fix: add the shift type to the `aria-label` ("صباحي ومسائي") and a letter or icon, or a shape difference, on the dots.
5. **Text that fails 4.5:1 through opacity modifiers** (R-25). Computed on the real tokens (light theme, white card): `text-muted-foreground/50` 2.18:1 (9 uses: placeholders like "—" and "غير محدد" in `EmployeesList`, `SalaryBasics`, `CurrentSalaryData`, `ShiftStaff`), `/60` 2.64:1 (`MonthlyFingerprints.tsx:71`), `/70` 3.22:1 (`ShiftSchedule.tsx:938`, weekday headers of the roster), `/80` 3.95:1 (`SalarySettings.tsx:176`, `ShiftStaff.tsx:220`), `text-destructive/60` 3.12:1 (`EmployeesList.tsx:767,1137`). The six icon uses at `/80` in `ShiftManagement` are decorative next to text, so they are fine. Fix: plain `text-muted-foreground` (6.30:1) or `text-destructive-text`.

## MEDIUM

6. **Hub tabs are `role="tab"` without a `tablist`** (R-32). `attendance/EmployeesHub.tsx` and `ReportsHub.tsx` render the tab buttons with `role="tab"`, `aria-selected`, `aria-controls`, but their wrapper has no `role="tablist"` (the other tab strips do). Screen readers need the tablist parent to announce "tab 2 of 7". They also lack arrow-key navigation; every tab is a separate Tab stop, so the pattern is operable but heavy (7 stops on the employees hub).
7. **Loading states are silent** (R-27, C-4). Only `salary/PayrollReport.tsx` has `role="status"` for loading; the other pages print "جاري التحميل…" or show skeletons with no live region, so a screen-reader user hears nothing while a list loads. Error blocks are fine (they use `role="alert"` or toasts).
8. **Data tables have no header scope or caption.** `<th>` without `scope="col"` in `DailyView`, `EmployeeDetail`, `EmployeesList`, `ManualPunches`, and the salary pages; no `<caption>` or `aria-label` naming the table. Cell-to-header association depends on the reader guessing.
9. **Salary drawer has no initial focus and no focus return** (R-32). Beyond finding 2: `SalaryBasics` does not move focus into its drawer when it opens (the attendance one does), and neither returns focus to the opening button on close.
10. **Status dots with no text of their own** (C-4). `attendance/Reports.tsx:390` is `aria-hidden` and sits next to a label, which is fine. `PermissionReport.tsx:217` (`bg-current` dot) and the roster dots are the cases to check; the first has a label beside it.
11. **`title` as the only name on a few controls** (R-33). `ShiftSchedule.tsx` print/previous/next buttons now carry `aria-label` too (fixed earlier); remaining `title`-only icon buttons: search the files for `title=` without `aria-label` when fixing 4.

## LOW

12. **Raw `<input>` fields without `autoComplete`/`inputMode`.** Money and percentage fields use `type="number"`, which opens a numeric keypad, so this is minor. Search boxes could add `enterKeyHint="search"`.
13. **No skip link** on long pages. The module nav is a single row now, so the cost is small.
14. **Warning chips rely on tint plus text.** The "مسودة" chips now use `text-warning-text` (6.82:1 on the tint), so they pass; listed so the check is recorded.
