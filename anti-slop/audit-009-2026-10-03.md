Mode: AFTER (session override). Scope: medical and patient-facing client workflows under `client/src/pages`, `client/src/components/{patients,patient-details,examination,sheets,reports}`, `client/src/features/{patient-portal,doctor-portal,clinical-suite}`, `client/src/hooks/{examination,patient-details,patients}`, and medical router surfaces. This is a source inspection of the current worktree, not a statement about who introduced its existing changes.

Audit method: targeted source reads and searches; no browser, build, click-through, screen-reader, keyboard, or contrast measurements were run. Findings cite current source lines; runtime claims remain unverified.

## HIGH

1. **Focus is removed from editable clinical sheet fields without a visible replacement** (R-32, human, craftsmanship). `client/src/components/sheets/SheetPatientVisionBlock.tsx:96,115,131,141,150,159,168,177,195,207` uses `focus:outline-none` on patient, refraction, IOP, and other inputs, and several only change the underline color on focus. `client/src/components/sheets/FollowupTablesBody.tsx:92` uses `outline-none` and a pale focus background. Keyboard users may lose a visible current-field indicator, including in clinical documentation. Add a clearly visible `:focus-visible` indicator that works in the sheet’s on-screen theme and retain an intentional print style.

2. **Patient rows are interactive containers around other interactive controls** (R-26/R-32, human). In `client/src/components/patients/PatientsTable.tsx:312-316` the mobile patient `<Card>` is `role="button"` and handles click/keyboard, but contains a checkbox and action buttons (`:336-347`, `:361-455`). The desktop `<TableRow>` repeats the button role and keyboard handler at `:541-552`, with a checkbox and buttons in its cells (`:554` onward). Nested buttons inside a button-like control create conflicting keyboard and assistive-technology semantics; activating a child can also trigger row behavior. Use a separate patient link/button target beside sibling actions, not a row/card wrapper with nested controls.

## MEDIUM

3. **Examination submit control has no visible action name** (R-26/C-2, UI/human/copy). `client/src/pages/ExaminationForm.tsx:72-79` renders a submit button with a save icon and only whitespace in both loading and idle states. It does not identify the save action visually or in an accessible name. Give it visible text such as the existing Arabic save action, and use a loading label while submission is in progress.

4. **Several clinical and prescription actions are below the stated 44px mobile target** (R-03, layoutmobile). In `client/src/components/patients/PatientsTable.tsx:410-455`, mobile card actions use `h-9 w-9` (36px) for open, edit, print, and delete. `client/src/pages/PatientDetails.tsx:140,200` uses 36px icon buttons. The examination form’s cancel/save row at `client/src/pages/ExaminationForm.tsx:72-84` also has no mobile sizing or wrap rule. Raise small touch controls to at least 44px with spacing, and check the action row wraps at narrow widths.

5. **Examination-form tab strip mixes English section furniture into the Arabic screen and forces horizontal scrolling** (R-03/R-05/R-06, UI/copy/layoutmobile). `client/src/pages/ExaminationForm.tsx:27-57` marks its navigation “Sections” in uppercase with wide tracking, and sets a horizontal, no-wrap strip whose triggers have 100-180px minimum widths. This competes with the Arabic workflow and makes some tabs reachable only by horizontal scrolling on narrow screens. Remove the redundant English label and reflow the tab controls at phone and intermediate widths, keeping all labels visible and keyboard reachable.

6. **Medical module worktree changes have not been validated at runtime** (R-35/C-4, UI). Existing uncommitted edits touch `PatientHubShell.tsx`, `LasikExamSheet.tsx`, `ClinicalReportFrame.tsx`, sheet components, shared app navigation, and global mobile/responsive CSS. Their diff includes safe-area bottom navigation and global table overflow rules, which affect patient flows broadly. No route click-through, mobile-width pass, theme pass, or print preview was run for this audit. Validate the changed medical routes and shared shell behavior before accepting those edits; inspect clinical print pages separately from screen styling.

## LOW

7. **Visible medical status text and visual emphasis need a measured contrast check** (R-25, human). `client/src/components/patients/PatientsTable.tsx:424-425` uses `text-warning/90` on `bg-warning/10`, while the component’s status-dot/strip presentation is defined in `client/src/components/patients/PatientMedicalStatusBadges.tsx`. The direction document itself says not to assume white/orange or semantic pairs pass. Measure the actual token-resolved pairs in both themes and ensure each status remains text-labelled rather than color-only before claiming AA.
