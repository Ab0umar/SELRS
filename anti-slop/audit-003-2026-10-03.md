# Salary UI anti-slop audit 003

**Date:** 2026-10-03  
**Mode:** AFTER (session override)  
**Scope:** Salary and payroll client surfaces, routes, responsive behavior, accessibility, copy, states, comments, and monthly-report export affordances. The audit covered 13 surfaces: dashboard/layout, salary basics, penalties, commission pools, employee funds, payroll report, settings, shift hub, shift staff, shift payroll, shift schedule, absent report, and current salary data.  
**Method:** Parallel read-only inspection followed by deduplicated synthesis. No source files were edited.

## Executive summary

The salary module has useful domain structure, Arabic/RTL localization, semantic tables, and several deliberate mobile renderings. The highest-risk defects are repeated across screens:

- Keyboard users cannot operate many mobile/tablet disclosure rows because clickable `div` elements replace buttons.
- Query failures are often collapsed into empty arrays or default values, so failed data can look like a valid empty report.
- Icon-only actions and several form controls lack accessible names, label associations, adequate hit areas, or visible focus treatment.
- One shift payroll printout asserts deduction values of `0.00` and a fixed `صفحة 1 من 1` even when the underlying values/page count may differ.
- Tablet layouts frequently rely on desktop tables, fixed-width strips, or phone cards without a deliberate intermediate state.
- There is no verified, deterministic in-app monthly PDF download/export. Several reports call browser/native print, which may allow a user to choose Save as PDF, but that is not the same as a discoverable PDF export capability.

## Findings

### HIGH — hard-gate issues

#### F-001 — Clickable disclosure rows are not keyboard-operable

- **Rules:** R-32, R-03
- **Files / locations:** `SalaryBasics.tsx:278-281, 553-556`; `SalaryPenalties.tsx:1099-1102, 1183-1186, 1264-1266, 1483-1485`; `PayrollReport.tsx:2629-2632, 2987-2990, 3384-3387, 4011-4014, 4150-4153`; `CurrentSalaryData.redesigned.tsx:264-267, 511-513`; `ShiftStaff.tsx:797-800`; `ShiftPayroll.tsx:491-522`; `AbsentReport.tsx:244-247, 262-266`.
- **Problem:** Primary mobile/tablet detail rows use clickable `div` elements without button semantics, focusability, Enter/Space activation, `aria-expanded`, `aria-controls`, or reliable accessible names.
- **Fix:** Use native disclosure buttons with localized names, visible focus, Enter/Space support, `aria-expanded`, and `aria-controls` tied to the detail region. Keep the hit area large enough for touch.

#### F-002 — Query failures and loading states are conflated with empty data

- **Rules:** R-27, C-4
- **Files / locations:** `SalaryBasics.tsx:162-166, 460-464, 666-678, 1439-1442`; `SalaryPenalties.tsx:76-88, 128-130, 189-215, 224-239, 424-429, 889-899, 1085-1088`; `CommissionPools.tsx:182-193, 235-262, 302-313, 670-678, 892-898, 1036-1041`; `EmployeeFunds.tsx:86-100, 371-407, 486-526`; `SalarySettings.tsx:39-83, 96-189, 193-433, 909-1065`; `ShiftStaff.tsx:309-316, 1067-1076`; `ShiftPayroll.tsx:200-206, 609-615`; `ShiftSchedule.tsx:322-345, 441-446, 1642-1665`; `CurrentSalaryData.redesigned.tsx:584-590, 832-868`; `PayrollReport.tsx:136-186, 2261-2281`.
- **Problem:** Many query results are coerced to empty arrays or defaults. Loading, failed requests, genuinely empty data, and partial data can therefore render the same UI. Some settings default an enabled state before the server response is known.
- **Fix:** Branch on each relevant query's `isLoading`, `isError`, and data status. Render localized loading and actionable error states with retry/refetch. Show empty/no-match copy only after a successful empty response, and keep independent report tabs from appearing complete when their dependencies fail.

#### F-003 — Desktop edit/delete and related controls lack accessible names

- **Rules:** R-32, R-04
- **Files / locations:** `SalaryBasics.tsx:236-260, 515-535`; `SalaryPenalties.tsx:868-884, 1416-1454`; `ShiftStaff.tsx:590-617`; `CurrentSalaryData.redesigned.tsx:222-246`.
- **Problem:** Edit, delete, save, and cancel controls expose only Pencil, Trash2, Check, X, or similar icons without localized `aria-label`, title, or visible text. Mobile text-labelled variants do not repair the desktop controls that remain active at large widths.
- **Fix:** Add contextual Arabic names such as `تعديل راتب`, `حذف راتب`, `تعديل عضو الشفت`, and `حذف عضو الشفت`, including the employee name where useful.

#### F-004 — Touch targets and focus indicators are too small or missing

- **Rules:** R-03, R-32
- **Files / locations:** `SalaryBasics.tsx:241, 258, 520, 533, 922-932, 1308-1335`; `SalaryPenalties.tsx:868-884, 1416-1454`; `EmployeeFunds.tsx:193-222, 393-400, 464-472, 512-519`; `SalarySettings.tsx:753-783, 791-860`; `ShiftHub.tsx:12-25`; `ShiftStaff.tsx:590-617`; `ShiftSchedule.tsx:1470-1476, 1835-1855, 2258-2267`; `CurrentSalaryData.redesigned.tsx:354-380, 809-827`.
- **Problem:** Several actions are 20–40px, including icon buttons, compact route buttons, switches, drawer close controls, and destructive actions. `SalarySettings` switches also use `focus-visible:outline-none` without a replacement focus indicator.
- **Fix:** Keep glyphs visually compact but give every interactive hit box at least 44x44px with separation. Add a high-contrast `focus-visible` ring to every control and verify light/dark themes.

#### F-005 — Commission-pool table inputs lack programmatic names

- **Rules:** R-32, C-4
- **File / locations:** `CommissionPools.tsx:1151-1201, 1323-1373, 1496-1546`.
- **Problem:** Desktop inputs for allowance amounts/counts and clinic consultant/specialist counts/rates rely on nearby visual cells and headers but have no stable id/label association or `aria-label`. Mobile duplicate cards have labels, but desktop controls remain active at large widths.
- **Fix:** Give every input a stable unique id and label or `aria-labelledby` combining the employee/row and column meaning.

#### F-006 — Salary-settings switches are unnamed

- **Rules:** R-32
- **File / locations:** `SalarySettings.tsx:772-856`.
- **Problem:** The first four employee commission/allowance switches expose `role=switch` and `aria-checked` but no accessible name. Only overtime has an `aria-label`.
- **Fix:** Give each switch a unique localized name containing the employee and the exact commission/allowance it controls.

#### F-007 — Current-salary form labels are not associated with controls

- **Rules:** R-32
- **File / locations:** `CurrentSalaryData.redesigned.tsx:736-778`.
- **Problem:** The employee select, basic salary input, and DateInput have sibling labels but no id/`htmlFor` association, so screen readers may not receive the intended names and clicking the label may not focus the control.
- **Fix:** Add stable ids and matching `htmlFor`; ensure DateInput forwards the accessible name.

#### F-008 — Shift route switcher exposes selected state visually only

- **Rules:** R-32
- **File / locations:** `ShiftHub.tsx:11-26`.
- **Problem:** The staff/payroll switcher looks like tabs but is a pair of plain buttons with no tablist/tab semantics, `aria-selected`, current-location indicator, or equivalent state.
- **Fix:** Use route links with a current-page indicator, or implement a real tab pattern with tablist, tab, `aria-selected`, and panel relationships. Do not communicate selection by color alone.

#### F-009 — Weekly shift-cycle editor has no tablet/mobile reflow

- **Rules:** R-03, R-35
- **File / locations:** `ShiftStaff.tsx:145-211`.
- **Problem:** The editor is permanently a seven-column grid. On phone and tablet widths each day becomes a narrow card containing two time inputs and multiple controls, with no intentional intermediate layout.
- **Fix:** Add a content-driven tablet state with fewer columns or a stacked day list, then a single-column narrow state. Verify through approximately 600–1024px and at 200% zoom.

#### F-010 — Absent-report responsive split has no deliberate tablet state

- **Rules:** R-03, R-35
- **File / locations:** `AbsentReport.tsx:177, 236`.
- **Problem:** The only breakpoint is `lg`: the desktop table is hidden below it and the phone/card layout is used for every smaller width. Tablet spacing, date-grid density, and hierarchy are not given a deliberate intermediate state.
- **Fix:** Add a compact table or intentional two-column/tablet arrangement where the content requires it; verify no overflow or cramped date tiles.

#### F-011 — Shift payroll printout asserts unavailable deduction values

- **Rules:** R-17, R-36
- **File / locations:** `ShiftPayroll.tsx:313-327`.
- **Problem:** The printable slip labels advances, debit balances, penalties, and total deductions but hardcodes every value to `0.00`, while only absence is sourced from the response. This can misstate payroll by presenting unavailable deductions as zero.
- **Fix:** Populate each deduction from the payroll response and calculate the total, or omit/label the fields as unavailable until the backend supplies them. Never print fabricated zero values.

#### F-012 — Shift payroll print footer hardcodes page count

- **Rules:** R-17, R-36
- **File / locations:** `ShiftPayroll.tsx:339-345`.
- **Problem:** The print footer always says `صفحة 1 من 1` even when multiple employee slips or page breaks create more than one page.
- **Fix:** Generate page numbering from the print/PDF renderer or omit page totals instead of asserting a fixed count.

### MEDIUM — purpose and responsive issues

#### F-013 — Multiple salary layouts fail at tablet/intermediate widths

- **Rules:** R-03, R-35
- **Files / locations:** `SalaryBasics.tsx:1271-1377`; `SalaryPenalties.tsx:610-643, 810-811, 904-983`; `CommissionPools.tsx:615-666`; `SalarySettings.tsx:633-879`; `ShiftPayroll.tsx:383-485`; `ShiftSchedule.tsx:1631-1639, 1667-1673`; `CurrentSalaryData.redesigned.tsx:873-900`.
- **Problem:** Several screens use two-state or fixed-width layouts that fail between phone and desktop: crowded headers, wide tables, non-wrapping actions, horizontally scrolling tab strips, fixed-width settings tables, clipped 11-column payroll tables, mismatched schedule header/body columns at `md`, and four narrow summary cards at `sm`.
- **Fix:** Define breakpoints where content actually stops fitting. Stack or wrap controls, use compact cards or intentional contained overflow for genuinely tabular data, align header/body column counts, and verify the complete 600–1200px range plus 200% zoom.

#### F-014 — Salary navigation hierarchy is declared then flattened

- **Rules:** R-05
- **File / locations:** `SalaryLayout.redesigned.tsx:18-124, 133`.
- **Problem:** Meaningful navigation sections with labels and descriptions are flattened to item links before handoff to `OperationalModuleShell`. Unless the shell reconstructs grouping, the declared hierarchy and descriptions disappear.
- **Fix:** Pass grouped navigation sections to the shell, or explicitly render section headings/descriptions while keeping DOM and visual order aligned with the intended salary workflow.

#### F-015 — Dashboard uses zero staff as a proxy for uncalculated payroll

- **Rules:** R-36
- **File / locations:** `SalaryDashboard.redesigned.tsx:37-40`.
- **Problem:** `staffCount === 0` is used to show `لم يُحتسب كشف هذا الشهر بعد`. The code does not establish whether zero staff means an uncalculated payroll or a genuinely empty workforce.
- **Fix:** Base the state on explicit payroll/calculation status. Reserve the zero-staff message for a confirmed empty workforce and explain the next action.

#### F-016 — Annual raise is mixed into ambiguous salary totals

- **Rules:** R-17, R-36
- **File / locations:** `SalaryBasics.tsx:68-75, 87-99, 1057-1064, 149-156`.
- **Problem:** `الزيادة السنوية` is added directly to monthly-looking totals without saying whether the amount is monthly, annualized, or a one-time adjustment.
- **Fix:** Define the payroll-period treatment in calculation and copy. Separate annual raise from monthly gross where appropriate and label totals with period and currency context.

#### F-017 — Insurance deduction may be outside the selected payroll period

- **Rules:** R-17
- **File / locations:** `SalaryPenalties.tsx:237-249, 401-421, 465-489, 1345-1352`.
- **Problem:** Insurance deductions are loaded as each employee's latest salary basics rather than the selected payroll period, yet `handlePrint` includes them in the monthly deductions report. The insurance tab also has an empty heading region, so period scope is unclear.
- **Fix:** Query/select the insurance value effective for the selected period and label its effective date, or clearly separate it from monthly deductions with visible period-scope copy.

#### F-018 — Shift duration labels do not match configured values

- **Rules:** R-36
- **File / locations:** `ShiftStaff.tsx:51-54, 456-472, 680-706, 929-930`.
- **Problem:** The UI repeatedly calls the editable base rate a 6-hour shift, but `calculatedFourHourShiftRate` uses user-entered `mainShiftHours` and the form allows 0.25–24 hours.
- **Fix:** Use the configured duration and clear units in labels and headers, or constrain the feature to six hours and validate that constraint.

#### F-019 — Employee-funds print summary uses an ambiguous measure label

- **Rules:** R-17, R-36
- **File / locations:** `EmployeeFunds.tsx:573-587`.
- **Problem:** The print summary labels `data.totalRevenue` as `إجمالي المبلغ` while the table lists per-member payouts. Users can interpret the revenue figure as total disbursed amount.
- **Fix:** Use precise copy such as `إجمالي إيرادات الفترة` and, if needed, add a separate `إجمالي المبلغ المصروف` computed from payout rows.

#### F-020 — Shift schedule queries payroll but presents only a roster

- **Rules:** R-05
- **File / locations:** `ShiftSchedule.tsx:335-338, 1571-1579, 804-822`.
- **Problem:** The module queries `computeShiftPayroll` for managers but renders only a roster/calendar; its `طباعة` action prints the roster, not payroll totals or a monthly salary report. The salary/payroll boundary is unclear.
- **Fix:** Label the surface explicitly as shift scheduling only, or render period/currency/calculation-status payroll output and add a truthful export path for that report.

#### F-021 — Current salary data has inert Download and Filter controls

- **Rules:** R-08
- **File / locations:** `CurrentSalaryData.redesigned.tsx:393-403, 709-724`.
- **Problem:** The Download and Filter buttons look functional but have no `onClick` or implementation. `تحميل` does not identify a format or scope.
- **Fix:** Wire each control to real behavior or remove/disable it honestly. Name export explicitly, such as `تصدير تقرير الرواتب PDF`, only when a real PDF export exists, and label the supported filter scope.

#### F-022 — Monthly PDF export is not a verified product capability

- **Rules:** Purpose gate, R-08, R-26
- **Files / locations:** Dashboard/Layout `SalaryDashboard.redesigned.tsx:57-62`, `SalaryLayout.redesigned.tsx:86-89`; `SalaryPenalties.tsx:260-272, 432-561, 662-685`; `CommissionPools.tsx:570-1701`; `SalaryBasics.tsx:647-1529`; `EmployeeFunds.tsx:171-177, 464-471, 532-622`; `PayrollReport.tsx:744-768, 2097-2250`; `SalarySettings.tsx:1068-1087`; `ShiftPayroll.tsx:347-367, 600-603`; `ShiftSchedule.tsx:804-822, 1571-1579`; `AbsentReport.tsx:135-147`.
- **Problem:** Several report surfaces invoke browser/native printing, which may let a user choose Save as PDF, but no audited surface exposes a deterministic PDF generation/download with filename and export status. Other surfaces expose no report export at all, and one Download control is inert. ShiftSchedule prints a roster rather than payroll.
- **Fix:** Confirm the intended owner of monthly reporting. If PDF export is required, expose a clearly labelled action at the actual report surface, include the selected period/variant, generate or download a deterministic PDF with a meaningful filename, and show loading/success/error states. If browser Save as PDF is the intended behavior, label it honestly as print/save-to-PDF.

### LOW — quality and copy issues

#### F-023 — Generic section-label comments add scan noise

- **Rule:** R-31
- **Files / locations:** `SalaryLayout.redesigned.tsx:18`; `SalaryBasics.tsx:113, 417, 647, 657, 660, 680, 708, 871, 883, 896, 936, 941, 974, 1031, 1057, 1067, 1232, 1265, 1339, 1379, 1486, 1499`; `SalaryPenalties.tsx:83, 128, 150, 189, 203, 224, 260, 424, 431, 563, 691, 795, 1075, 1159, 1243, 1345`; `CommissionPools.tsx:572, 621, 668, 842, 986-987, 1124-1126, 1219, 1252, 1391, 1424, 1675`; `ShiftPayroll.tsx:527, 543, 572, 608, 620`; `SalarySettings.tsx:724, 767, 786, 805, 824, 843`; `CurrentSalaryData.redesigned.tsx:147-149, 184-185, 409, 600, 609, 697, 728, 802, 804, 853, 872`; `AbsentReport.tsx:68`.

#### F-024 — Decorative icons are not consistently hidden from assistive technology

- **Rule:** R-04 / C-4
- **Files / locations:** `EmployeeFunds.tsx:275, 208, 220, 231, 235, 366, 461, 504, 399, 518`; `SalarySettings.tsx:59, 134, 439, 505, 963, 979-983`; `ShiftSchedule.tsx:863-872, 1289-1293, 1328-1340, 1341-1349`.
- **Problem:** Decorative Lucide icons next to already visible labels are not explicitly `aria-hidden`. Depending on shared icon defaults, assistive technology may announce redundant or meaningless graphics.
- **Fix:** Mark purely decorative icons `aria-hidden="true"`; expose an accessible name only when the icon itself conveys unique information.

#### F-025 — Arabic report copy needs grammatical and terminology cleanup

- **Rule:** R-36
- **Files / locations:** `PayrollReport.tsx:2922-2929`; `CurrentSalaryData.redesigned.tsx:161-162, 312-317`.
- **Problem:** `لا توجد موظفي شفتات تطابق البحث` is grammatically awkward, and `علاء معيشة` appears to be a typo for `علاوة معيشة`.
- **Fix:** Use `لا يوجد موظفو شفتات يطابقون البحث` and confirm one consistent domain term, likely `علاوة معيشة`.

## Strengths worth preserving

- SalaryDashboard distinguishes loading, error, empty, draft, and final-status branches, includes retry feedback, and uses `aria-live`.
- Multiple reports and tables use semantic markup, scoped headers, RTL direction, and period metadata.
- Arabic labels and RTL layout are used consistently across the salary surfaces.
- Many screens provide deliberate mobile card alternatives or separate mobile/desktop branches instead of merely shrinking a desktop table.
- Mutation success/error feedback is commonly surfaced with toast messages, and destructive deletes or roster clearing generally use confirmation prompts.
- PayrollReport has base-query loading/error/retry states, native tab semantics, period-specific status, escaped print HTML, RTL UTF-8 output, A4 landscape styling, and print cleanup.
- AbsentReport has visible loading, actionable error/retry, explicit empty states, concrete period/employee/date totals, scoped headers, and focused A4 print styling.
- ShiftPayroll provides native date controls, period-specific empty states, Enter/Escape editing behavior, scoped headers, responsive summary cards, RTL/A4 print styling, and mutation feedback.
- ShiftSchedule has distinct mobile and desktop calendar branches, large mobile calendar buttons, native labelled dialog controls, roster states, destructive confirmation, and escaped RTL A4 print output.
- CommissionPools separates center and clinic workflows, uses semantic tables and mobile cards, and disables saves while pending.
- SalarySettings separates deductions, global rates, employee settings, and late tiers; employee data has loading/empty/filtered-empty states and semantic table markup.
- EmployeeFunds validates dates, positive amounts, and names; its print layout has RTL/A4 styling and headings/scopes.
- ShiftStaff validates cycle end times, distinguishes Friday as non-editable, confirms generated-shift deletion, and includes useful feedback for several operations.
- Salary navigation labels and destinations are domain-specific and cover basics, monthly variables, payroll, shifts, and settings.
- CurrentSalaryData and SalaryBasics provide clear page-to-section hierarchy, semantic desktop tables, explicit loading/empty messages, native form controls, mutation feedback, and delete confirmations.

## Monthly PDF/export conclusion

No product-wide deterministic PDF export can be verified from the audited surfaces. Several screens support browser/native printing, which may allow manual Save as PDF, but the module does not consistently provide a labelled PDF export action, generated file, meaningful filename, selected-period metadata, or export success/error state. Confirm which surface owns monthly salary-report export before implementation.
